# تست با حساب واقعی رشد

زمان اجرای نهایی: ۱۱ نوامبر ۲۰۲۶، ساعت ۱۸:۴۲ UTC / ۲۳:۱۲ کابل.

آزمون از طریق `ConnectionsManager` و parserهای واقعی اپ روی JVM اجرا شد. شبیه‌ساز و گوشی واقعی استفاده نشدند. نام کاربر و رمز از ورودی مخفی گرفته شدند؛ مقدار رمز، bearer، کلید خصوصی و سطرهای شاگردان در فایل‌های گزارش ذخیره نشدند.

| مرحله | نتیجه |
| --- | --- |
| ورود با حساب ارسالی | HTTP 200؛ موفق |
| خواندن پاسخ ورود با `Session.login` | موفق؛ `ScannerOperator`، محدودهٔ یک مکتب |
| دریافت configuration | HTTP 200؛ سال جاری موجود؛ دورهای ۱ تا ۱۲ باز |
| دریافت فهرست امتحان‌های صادرشده | HTTP 200؛ یک صفحه، صفر مورد، بدون cursor بعدی |
| ثبت دستگاه آزمایشی با proof نسخهٔ ۲ در bundle | موفق؛ کلیدهای جداگانهٔ P-256 برای امضا و رمزگذاری |
| دریافت Lite bundle دور ۱ | HTTP 200؛ `roshd.information-bundle.v2`، `qr-lite-v1`، `complete: true` |
| تطبیق دوره، محدوده، configuration و رسید کلید دستگاه | موفق |
| محتوای bundle | ۱۲ تعریف امتحان؛ صفر شاگرد؛ صفر بستهٔ پاسخ‌نامه |
| لغو دسترسی دستگاه آزمایشی | موفق؛ تنها دستگاه ساخته‌شده در همین آزمون لغو شد |
| خروج از نشست ساخته‌شده در آزمون | موفق |

تمام صفحه‌های کشف امتحان با `limit=100` و پیگیری `nextCursor` بررسی شدند؛ نتیجهٔ خالی فقط از مشاهدهٔ صفحهٔ اول نتیجه‌گیری نشده است. API کشف، امتحان‌های دارای برگهٔ صادرشده را می‌دهد، در حالی که bundle تعریف امتحان‌های بدون برگه را هم شامل می‌شود؛ بنابراین صفر بودن کشف و ۱۲ بودن تعریف‌های دور ۱ با هم ناسازگار نیستند.

قابلیت‌های مرتبطِ اعلام‌شده در سرور: `singleScan`، `batchScan`، `imageFirstUpload`، `originalImageUpload`، `zipImageParts` و `offlineCorrectCount` فعال‌اند؛ `offlineScore` غیرفعال است. فعال‌بودن این flagها به معنی آزموده‌شدن ارسال نیست. مسیر حاضری فراخوانی نشد.

دور ۱ انتخاب صریحِ harness آزمایش بود؛ تنظیمات دور در برنامهٔ اندروید کاربر تغییر نکرد. دستگاه و کلیدها برای همین آزمون ساخته شدند؛ کلید خصوصی در حافظه باقی ماند و ذخیره نشد. در پایان، دسترسی دستگاه آزمایشی لغو شد و نشست تست خروج کرد. هیچ شاگرد، پاسخ، نمره یا عکس آزمایشی به نام شاگردان ثبت نشد.

به‌دلیل نبودن شاگرد و بستهٔ پاسخ‌نامهٔ صادرشده، دریافت و تأیید امضای یک roster واقعی، خواندن برگهٔ واقعی، ارسال scan، ادامهٔ آپلود عکس و دریافت نتیجه در این حساب قابل آزمون نبود. قالب این مراحل در تست‌های محلی بررسی شده است، اما این گزارش آن‌ها را آزمون زندهٔ موفق حساب نمی‌شمارد. رابط، دوربین و Android Keystore روی گوشی نیز اجرا نشدند؛ کلیدهای P-256 آزمون در JVM ساخته شدند.

آزمون opt-in در `app/src/test/kotlin/com/haseebullahjan/roshd/core/AuthenticatedRoshdApiTest.kt` موجود است. اجرای دوباره:

```sh
# ورود، تنظیمات و کشف امتحان؛ بدون ساخت دستگاه
python3 tools/run_authenticated_api_test.py

# افزون بر موارد بالا: دریافت دور ۱ با دستگاه آزمایشی و سپس لغو دسترسی همان دستگاه
python3 tools/run_authenticated_api_test.py --bundle
```

هر دو دستور نام کاربر و رمز را با ورودی مخفی می‌گیرند. Gradle با یک worker، heap حداکثر ۷۶۸ MiB و بدون daemon دائمی اجرا می‌شود. بدون opt-in، تست حساب در اجرای معمولی skip می‌شود.

شواهد: `retest-1.1.14-auth.log`، `retest-1.1.14-auth-first.xml`، `retest-1.1.14-auth-final.xml` و `retest-1.1.14-auth-summary.json`. اجرای نهایی در ۴۱ ثانیه با `BUILD SUCCESSFUL` پایان یافت؛ بخش آزمون حساب حدود ۲۰ ثانیه بود. APK و کد اجرایی برنامه در این مرحله تغییر نکردند.
