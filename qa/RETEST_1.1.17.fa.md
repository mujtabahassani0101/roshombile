# تست دوبارهٔ رشد 1.1.17

به درخواست کاربر در ۲۰۲۶-۱۱-۱۲، تست‌ها دوباره اجرا شدند. نتیجه‌ها از اجرای تازه‌اند؛ APK و کد تولیدی تغییر نکردند. گوشی متصل نبود و شبیه‌ساز اجرا نشد.

| بررسی تازه | نتیجه |
| --- | --- |
| JVM با `testDebugUnitTest --rerun` | ۱۵۱ موفق، صفر شکست؛ ۷ تست زنده غیرفعال |
| ابزارهای Python / SQL | ۱۳ موفق |
| CTest موتور بومی | هر ۹ تست موفق؛ مورفولوژی، پاسخ، QR، نوع، هندسه، نرمال‌سازی، جهت زندهٔ هسته، C ABI و قالب |
| صف موازی بومی | موفق؛ ۵۶۰ پاسخ معلوم، FIFO، دو انجین پاسخ، یک هدر و ۹ درخواست هم‌زمان |
| هم‌پوشانی دو انجین پاسخ | 775.804 ms در اجرای میزبان |
| برگهٔ بازنشسته | QR چاپی و حالت fixed رد می‌شوند؛ موتور پاسخ اجرا نمی‌شود |
| T1/T3 و هشت حالت EXIF | در هر یک از ۳ اجرای مستقل، ۱۰ تصویر مصنوعی و ۹۴۰ پاسخ درست؛ صفر خطا |
| نمرهٔ صفر، اعشاری، نبود کلید/سیاست و پاسخ مبهم | تست‌های JVM موفق |
| عکس خودکار روی چاپ مشابه/QR متفاوت، قفل تکرار و تازگی QR | تست‌های منطقی JVM موفق |
| قالب‌های APK | فقط ۴۰ و ۱۰۰؛ قالب و عکس پیش‌نمایش ۶۰ وجود ندارد |
| تطبیق سورس آزموده‌شده با سورس تحویلی | SHA-256 تعداد ۲۶۹ فایل مرتبط اپ/هسته/تست با فایل ZIP تحویلی برابر است |
| سلامت APK | ZIP سالم و SHA-256 همان APK تحویلی |

با چهار نخ OpenCV روی کامپیوتر Linux x86_64، خواندن تک‌عکس ۱۰۰سؤاله 282.149 ms و ۴۰سؤاله 296.441 ms طول کشید؛ هر دو خوانش اضافه هم از نظر پاسخ‌ها کنترل شدند. زمان دستهٔ ۱۰تصویری 2103.73 ms و بیشینهٔ RSS همان فرآیند 113040 KiB بود. این اعداد شامل CameraX، ذخیره، رمزگشایی کلید، نمره‌دهی یا نمایش Android نیستند.

آزمایش‌های فعلی روی JVM، SQLite و موتور بومیِ میزبان انجام شدند. **عکس‌گیری واقعی خودکار، ارتباط CameraX با صف، نمایش نمره روی رابط گوشی و تأخیر کامل روی Android در این نوبت اجرا نشدند**؛ خروجی `adb devices -l` خالی بود. نتیجهٔ مصنوعی تضمین دقت روی عکس واقعی نیست. هفت تست زندهٔ API هم اجرا نشدند و هیچ نمره/پاسخ‌نامه‌ای در سرور ثبت نشد.
