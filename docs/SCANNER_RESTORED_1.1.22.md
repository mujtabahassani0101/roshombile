# بازگردانی اسکنر قبلی با برگهٔ جدید — رشد 1.1.22 / 4208

مطابق تأیید کاربر، اسکنر قبل از نسخهٔ 1.1.21 از سورس پشتیبان 1.1.20 بازگردانده شد. ۲۵ فایل سورس، مدل، هدر، مجوز و runtime دقیقاً همان bytes پشتیبان را دارند. مدل‌های `border.mnn` و `dewarp.mnn`، runtimeهای MNN برای ARM، هدف `paperframe_inference` و کلاس‌های اصلی تشخیص لبه، رهگیری، پرسپکتیو، صاف‌سازی و کش بازگشته‌اند.

`ScannerActivity` دوباره به `PaperframeScanner` وصل است. پل `paperframe.*` و صفحهٔ تنظیم دستی چهار گوشه، چرخش و خوانش نیز بازگردانده شدند. مدل‌ها مثل قبل هنگام استفاده و در worker بار می‌شوند؛ شروع برنامه آن‌ها را بی‌دلیل بار نمی‌کند. خودکاربودن عکس، قفل عکس تکراری، صف پایدار، دو worker پاسخ، نمرهٔ موقت، نسخهٔ سرخ/سبز و ارسال گروهی حفظ شده‌اند.

**برگهٔ جدید حفظ شد:** PDF اصلاح‌شدهٔ ۱۰۰سؤالی، پیش‌نمایش آن و مختصات OMR دقیقاً با نسخهٔ 1.1.21 یکسان‌اند. رجیسترکردن نشانه‌های همین برگه در OMR باقی است تا برگه پس از صاف‌سازی درست خوانده شود. قالب ۴۰سؤالی عوض نشده و ۶۰سؤالی برنگشته است. اصل عکس‌ها، پاسخ‌ها، امضاها، داده‌های ذخیره‌شده و حساب‌ها حذف نشده‌اند.

Runtime مدل‌های تأمین‌شده ARM است. روی شبیه‌ساز x86، اسکنر از مسیر OpenCV اصلی خود استفاده می‌کند؛ نتیجهٔ تست x86 شاهد اجرای مدل عصبی ARM نیست. برای بررسی کامل کیفیت صاف‌سازی عصبی، دوربین و نور واقعی، تست روی گوشی ARM لازم است. برگهٔ خام جدید فقط جایگاه QR دارد و برای شناسایی شاگرد باید QR معتبر چاپ شود.

آزمون اختصاصی `scanner-restore` در بستهٔ جداگانهٔ `.nativeqa`، عکس‌های مصنوعی T1/T3 را روی زمینهٔ تیره می‌گذارد، از مسیر واقعی import/تشخیص گوشه/render/چرخش می‌گذراند و نتیجه را به OMR جاری می‌دهد. شمار سؤال‌ها، تمام گزینه‌های معلوم، مختصات لازم برای رنگ‌گذاری و حفظ hash اصل عکس بررسی می‌شوند. این تست به حساب واقعی یا ارسال نمره به سرور نیاز ندارد.

گزارش اجرا و ممیزی APK در `qa/VALIDATION.md` ثبت می‌شود. شبیه‌سازی و ساخت به ترتیب انجام می‌شوند تا RAM هم‌زمان برای هر دو مصرف نشود.
